# Konami 053248 physical measurements

Work for [JTKCPU issue 1](http://gitea.jotego.es/jotego/jtkcpu/issues/1), measured
on the user's Vendetta PCB in September 2026. These observations apply to this
053248 specimen and the recorded operands. They are not a specification for
every Konami CPU variant or every operand combination.

## Board and measurement setup

The CPU has one **12 MHz CLK input**, confirmed by the user. There are no
M6809-style E/Q pins. Report durations as input-clock periods; do not divide by
four and label the result as a measured E-clock count.

The original program ROM is 128 KiB, with A16 on socket pin 2. The installed
PicoROM is the original **POG** variant, running the task's experimental
`POG_27C020_70ns` firmware `jtkcpu-1.6`. P32 firmware has a different GPIO map
and did not operate correctly on this device.

The validated image is 128 KiB, with PicoROM `addr_mask=0x1ffff`:

| CPU address | Physical PicoROM offset | Use |
|---|---|---|
| 8000 | 18000 | Reset/bootstrap code |
| DC00–DFFF | 1DC00–1DFFF | Reserved communications block |
| FFFE–FFFF | 1FFFE–1FFFF | Reset vector, value 8000 |

The external PicoROM reset lead is disconnected. Reprogramming disables ROM
service for at least three seconds, ends the old capture, writes and reads back
the entire image, arms communications, then resumes ROM service. The PCB's
watchdog supplies the reset. A distinct boot marker and complete record stream
are required to accept the subsequent run.

## Mapper and watchdog initialization

Preserve the original program's first 26 bytes, including its delay and scroll
chip memory-mapper programming:

```asm
        LDX #$8000
delay:  LEAX -1,X
        BNE delay
        TST $5FEA
        LDA #$11
        STA $7C00
        LDA #$FB
        STA $5D00
        ORCC #$D0
```

The mapper exists in the FPGA core but is not modeled by local MAME. Omitting
its initialization can invalidate accesses to tile-related logic. The probes
subsequently disable board IRQ/EEPROM outputs through 5FE2, set INIT through
5FE0, select bank zero, and test work RAM without a stack before using RAM.

Reading 5FEA every few microseconds did **not** keep this physical watchdog
alive: boot markers repeated approximately every 0.693 seconds. Spacing reads
approximately 169 ms apart produced stable execution. Later ten-second probes
also passed at approximately 10.6 ms, 2.65 ms and 0.664 ms between reads. These
are bounded observations, not a determination of the minimum safe spacing or
the internal watchdog circuit. Do not reinstate the old per-byte watchdog loop.

## Timing method

The CPU emits case/start/end markers by reading PicoROM's address-triggered
communications region. RP2040 timestamps have microsecond resolution. A fit
`T(N) = H + N*C` over repeated blocks isolates instruction cost from fixed
setup/marker overhead. Typical repetition counts are 0/128/256/512; controlled
operand and addressing cases use 0/64/128/256.

For operand-dependent instructions, each repeated unit reloads its operands
and CC. A separate setup-only slope is measured and subtracted. This avoids
mistaking repeated execution on an evolving operand for fixed-operand timing.

Acceptance requires at least four samples at every block size, one boot marker,
complete ordered trace records, no drops, fit residuals no greater than 2 us,
and a fitted count within 0.15 CLK of an integer. Those are analysis gates,
not an independent calibration of CLK accuracy. This method does not directly
capture instruction-fetch boundaries or input-clock edges. NOP resolves to
four input-clock periods with this method.

All 197 known primary opcodes have timing samples, but addressing, operand,
branch and variable-length coverage remains partial. Opcode F0 BSWI is marked
JT-specific in the RTL and is excluded from the physical known-opcode sweep.

## Stronger flag matrices

CC is captured with `PSHS CC` immediately after the tested instruction.
Instruction dispatch and register setup happen before restoring initial CC.
CPU-generated CRC-16 records include inputs and outputs; host acknowledgement
prevents FIFO overrun. Source/image hashes, record IDs, independent trace events,
preserved registers and completion markers accompany each accepted batch.

### LMUL

All 256 initial CC values were tested for each of these 12 X,Y pairs:

```
0000,0000  0001,0001  FFFF,FFFF  8000,0002
55AA,AA55  1234,5678  8000,0001  0001,8000
FFFF,0001  0100,0100  FFFF,8000  8001,FFFF
```

For all 3,072 records, X:Y receives the unsigned 32-bit product, Z describes
whether that full product is zero, and **all other CC bits are preserved**.
D=1234 and U=2F20 remain unchanged. In particular, C is preserved with both
product bit 15 and bit 31 set. This differs from local MAME's bit-15 C rule and
the current FPGA ALU's bit-31 C rule.

### DIV X,B

All 256 initial CC values were tested for each of these 12 X,B pairs:

```
0000,01  0001,01  FFFF,01  FFFF,FF
8000,02  1234,56  0000,00  FFFF,00
0001,02  7FFF,01  8000,01  8000,00
```

For nonzero divisors, X receives the unsigned quotient and B the remainder.
N/Z describe the quotient; **all other CC bits are preserved**. The recorded
zero-divisor inputs produce X=FFFF and B=the dividend's low byte. A=12, Y=2F10
and U=2F20 remain unchanged. Current RTL excludes DIVXB from N updates, while
local MAME also changes C and returns zero for divisor zero; these differ from
the physical records.

A separate timing sample set of 16 nonzero-divisor and 16 zero-divisor pairs
fits these candidate rules:

| Condition | Input CLK periods |
|---|---:|
| B != 0 | 25 + bit 0 of the integer quotient |
| B == 0 | 26 − bit 15 of the dividend |

For example, 7FFF/0 takes 26 CLK and 8000/0 takes 25 CLK, despite identical
FFFF quotients. These formulas are fits to the sampled inputs, not exhaustive
operand proofs.

### NEG and ABS

NEGA, NEGB, NEGD, ABSA, ABSB and ABSD were each tested with zero, the
most-negative value, +1 and -1, across all 256 initial CC values: 6,144
records. The unused byte of D and X/Y/U remained unchanged. For this matrix:

| Flag | NEG | ABS |
|---|---|---|
| N | Sign bit of the result | Sign bit of the result |
| Z | Result is zero | Result is zero |
| V | Input is the most-negative value | Input is the most-negative value |
| C | Input is nonzero | Input is negative |
| E/F/H/I | Preserved | Preserved |

The most-negative value remains unchanged after two's-complement negation
or absolute value and produces N=V=C=1, Z=0. Zero produces N=V=C=0, Z=1.
ABS(+1) clears N/Z/V/C, whereas ABS(-1) produces +1 with C set.
The current RTL excludes ABS from Z updates and explicitly clears its C;
both differ from these physical observations. Additional operand values
remain to be tested.

Separate paired timing tests reload the operand and CC50 before every
execution. All four recorded values take the same time within each opcode:
NEGA/NEGB/ABSA/ABSB take 5 input CLK periods, NEGD takes 7, and ABSD takes 8.
The setup-only slope is measured independently (30 CLK) and subtracted.

### CLR, COM, SEX, INC and DEC

Two further matrices contain 6,144 records each: six primary opcodes, four
recorded inputs each, and all 256 initial CC values. The first covers
CLRA/CLRB/CLRD, COMA/COMB and SEX, using zero, the most-negative value, +1 and
-1. There is no register COMD in the known opcode inventory. The second covers
INCA/INCB/INCD and DECA/DECB/DECD; INC uses zero, the most-negative value, the
largest positive value and -1, while DEC uses zero, the most-negative value,
+1 and -1.

For those inputs, E/F/H/I are preserved and the remaining flags behave as
follows:

| Operation | N | Z | V | C |
|---|---|---|---|---|
| CLR | 0 | 1 | 0 | 0 |
| COM | Result sign | Result is zero | 0 | 1 |
| INC | Result sign | Result is zero | Input is largest positive value | Preserved |
| DEC | Result sign | Result is zero | Input is most-negative value | Preserved |
| SEX | Original B bit 7 | Inverse of original B bit 7 | 0 | Preserved |

**SEX does not set Z from the full D result on this specimen.** B=01 produces
D=0001 with Z=1. A separate confirmation used the earlier single-record format,
no opcode dispatch, and twelve B values at CC00..07. A further sweep tested
all 256 B values at CC00/FF with initial A=5A, plus 64 cases varying initial A.
All 672 additional records agree with the mapping above. The four original
B values (00,01,80,FF) cover all 256 initial CC states.

This behavior is consistent with N/Z describing the generated A byte (00 or
FF), rather than D; it does not establish the internal implementation. The
current RTL uses the full D result for SEX's Z flag. The initial full-D
hypothesis is retained with its mismatches in the task reports.

The newer transport packs two eight-byte records into each CRC-protected
payload. Each record echoes input D, opcode and initial CC, then reports output
D, output CC and a guard byte. X/Y/U are checked on the CPU after immediate
D/CC capture. A 192-record NEG/ABS comparison against the earlier format
passed, including a host polling stall and USB-interface close/reopen.

### Fixed byte shifts, rotates and TST

A/B forms of LSR, ROR, ASR, ASL, ROL and TST were tested with byte operands
00, 80, 01 and FF across all 256 initial CC values: 12,288 records. Data,
the unused D byte and CPU-side X/Y/U guards match the expected operations.
Both byte rotates include the incoming carry in their data result.

| Operation | N | Z | V | C |
|---|---|---|---|---|
| LSR, ROR, ASR | Result sign | Result is zero | Preserved | Shifted-out bit |
| ASL | Result sign | Result is zero | Result sign XOR shifted-out bit | Shifted-out bit |
| TST | Operand sign | Operand is zero | 0 | Preserved |
| ROL | Preserved | See below | Preserved | Shifted-out bit |

E/F/H/I are preserved throughout these matrices. **ROL has an additional
observed exception:** with incoming C=1, Z is preserved; with incoming C=0,
Z describes whether the result is zero. For example ROLA with A=FF and
CC=05 produces A=FF and CC=05, while CC=00 produces A=FE and CC=01.
The ordinary result-N/Z hypothesis fails; the alternative rule above fits
all 2,048 ROLA/ROLB observations.

A separate direct-instruction probe, without opcode dispatch and using the
earlier full-register record format, adds 1,344 matching observations. For
each opcode it covers twelve operands at eight CC presets, every byte value
at CC00/05, and 32 further operands at CC0E/FF. X/Y/U are checked on the host.
Thus all byte operands are covered at those two CC values; all 256 initial
CC values remain covered only for the original four operands. The full
operand-by-CC Cartesian product has not been measured. Current RTL updates
N/Z from the result and sets V from the sign transition for byte ROL; these
differ from the recorded physical behavior.

Separate controlled timing tests cover RORA/RORB/ROLA/ROLB with operands
00 and FF and incoming C=0/1. All 16 cases resolve to 4 input CLK periods,
after subtracting the measured setup-only slope of 30 CLK. These fixed byte
rotate results must not be generalized to the variable-count word rotates.

### Extended-RAM byte and word operations

A separate sweep adds 2,016 records across 21 memory opcodes: byte CLR, COM,
NEG, INC, DEC, TST, LSR, ROR, ASR, ASL and ROL; word LSRW, RORW, ASRW, ASLW,
ROLW, CLRW, NEGW, INCW, DECW and TSTW. Each uses extended address 2F40,
twelve selected operands and initial CC00/01/04/05/08/09/72/FF. Operands cover
zero, small positives, sign/overflow boundaries, alternating bits and values
near the unsigned maximum. This is not all-CC or all-addressing coverage.

Each ROM executes one fixed opcode, captures CC immediately, and reports the
resulting RAM value plus D/X/Y/U. D=1234, X=2F00, Y=2F10 and U=2F20 remain
unchanged. The CPU checks A5 and 5A sentinels immediately before and after the
byte or word operand. Every data and guard check passes; E/F/H/I are preserved
for the recorded presets.

Byte memory operations match the corresponding recorded register models,
including the byte ROL exception: N/V preserved, C=old bit 7, and Z preserved
when incoming C=1, otherwise result-zero. The ordinary result-N/Z model fails
58 of the 96 byte-memory ROL observations.

Fixed word operations have these observed rules:

| Operation | N | Z | V | C |
|---|---|---|---|---|
| LSRW, RORW, ASRW | Result sign | Result is zero | Preserved | Old bit 0 |
| ASLW, ROLW | Result sign | Result is zero | Input sign XOR result sign | Old bit 15 |
| CLRW | 0 | 1 | 0 | 0 |
| NEGW | Result sign | Result is zero | Input 8000 | Input nonzero |
| INCW | Result sign | Result is zero | Input 7FFF | Preserved |
| DECW | Result sign | Result is zero | Input 8000 | Preserved |
| TSTW | Operand sign | Operand is zero | 0 | Preserved |

Both fixed word rotates use incoming carry in the data result. **ROLW does
not share the byte ROL flag exception** in this sample. For example, input
4000 at CC00 rotates to 8000 with CC0A. The candidate preserving V disagrees
with 48 of 96 ROLW records; the sign-change model fits all of them. Keep these
fixed word operations distinct from the variable-count word rotations.

### DAA and TSTD

The DAA matrix contains all 256 A values at CC00/01/20/21/DE/DF/FE/FF,
with B=A5, plus 64 cases varying B: 2,112 records. All four incoming H/C
combinations are covered with two presets for the other flags. B and X/Y/U
remain unchanged. A separate TSTD probe covers twelve word values at eight
CC presets (96 records): D is unchanged, N/Z describe full D, V clears and
E/F/H/I/C persist.

All sampled DAA results and flags fit the following model, with A and CC
referring to inputs:

```text
low  = 0x06 if H or (A & 15) > 9 else 0
high = 0x60 if C or A > 0x99 else 0
sum  = A + low + high
Aout = sum & 255
Hout = ((A & 15) + low) > 15
Cout = Cin XOR (sum > 255)
Vout = 0
N/Z  = preserved if high != 0, otherwise describe Aout
E/F/I = preserved
```

This differs from the current RTL model, which preserves H, ORs incoming C
with carry-out, and always updates N/Z. That model disagrees with 1,662 of
2,112 flag observations, while the A data matches throughout. Earlier candidate
rules gating N/Z only on incoming or outgoing C fail 211 and 215 records;
those hypotheses and mismatch indices remain in the reports.

A follow-up matrix adds 1,536 records: A=00/0A/94/99/9A/FF, each with all
256 initial CC values and B=A5. Every record matches the model above, including
independent N/Z values and all E/F/I/H/V/C combinations. The original RTL-like
candidate fails 1,184 of these confirmation records. This combines all A values
at eight presets with all CC values at six boundary operands; the full A-by-CC
Cartesian product remains unmeasured.

Sixteen controlled DAA timing cases cover A=00/0A/A0/FF and all four H/C
inputs. They take 8, 10, 11, 12, 13 or 14 input CLK periods and all fit:

```text
14 - (H ? 3 : ((A & 15) > 9 ? 1 : 0))
   - (C ? 3 : (A > 0x99 ? 1 : 0))
```

Each unit reloads D and CC; an independently measured 30-CLK setup slope is
subtracted. All 128 repeated-unit encoding bytes match separate assembly and
all timing/data guards pass. The formula fits these sixteen inputs; broader
timing operand coverage remains pending. Counting corrections alone does not
explain the different cost of a correction selected by a flag versus A.

### Short and long branches

All 32 ordinary short/long branch opcodes (60–7F) were tested across all
256 initial CC states with D=1234: 8,192 records. A further 64 cases use
D=FFFF and CC00/FF for each opcode. Every observed outcome matches the
condition predicate, and every CC bit remains unchanged. D/X/Y/U are also
preserved in the captured data and CPU guards.

Each branch uses a forward displacement of six bytes. Taken and untaken
paths each execute `PSHS CC` immediately after the tested branch, then save
D/CC and report a distinct outcome marker. Dispatch and register setup precede
`PULS CC`; no test or marker instruction intervenes before CC capture. The
assembled branch displacement and target's immediate capture instruction are
checked directly in each image.

| Short condition (long form agrees) | Taken CC states out of 256 |
|---|---:|
| BRA / BRN | 256 / 0 |
| BHI / BLS | 64 / 192 |
| BCC / BCS | 128 / 128 |
| BNE / BEQ | 128 / 128 |
| BVC / BVS | 128 / 128 |
| BPL / BMI | 128 / 128 |
| BGE / BLT | 128 / 128 |
| BGT / BLE | 64 / 192 |

These captures establish outcomes and flag preservation for this layout.
Other displacements, backward targets and boundary placements remain separate
coverage dimensions. The earlier branch timing records use their own layouts;
no timing count is inferred from this result-reporting loop.

### Byte loads, arithmetic, comparisons and logic

A further 3,840 records cover A/B forms of LD, ADD, ADC, SUB, SBC, AND, BIT,
EOR, OR and CMP in both immediate and extended-RAM forms: 40 primary opcodes.
Each has twelve operand pairs and CC00/01/20/21/DE/DF/FE/FF. Pairs include
00/00, 00/01, 01/FF, FF/01, 7F/01, 80/01, 80/FF, 0F/01, F0/10, 55/AA,
AA/55 and FF/FF. All 1,920 immediate/RAM record pairs agree exactly in output
D and CC, as well as the unchanged X/Y/U registers.

The recorded cases match these models; E/F/I are preserved throughout:

| Operation | H | N/Z | V | C |
|---|---|---|---|---|
| ADD/ADC | Carry out of bit 3 | Arithmetic result | Signed addition overflow | Carry out of bit 7 |
| SUB/SBC/CMP | Preserved | Subtraction result | Signed subtraction overflow | Borrow |
| AND/BIT/EOR/OR/LD | Preserved | Logical or loaded result | 0 | Preserved |

ADC adds incoming C and SBC subtracts incoming C. CMP and BIT preserve the
tested accumulator while reporting flags for the computed comparison or AND
result. The other byte of D remains unchanged, including when a zero byte
result occurs in a nonzero D value.

RAM sources occupy 2F40, with A5/5A sentinels at 2F3F/2F41. The CPU verifies
that the source and both sentinels remain unchanged. Immediate probes dispatch
to fixed ROM operand leaves before restoring CC; every leaf then executes the
literal instruction immediately followed by `PSHS CC`. Source/image hashes,
all literal encodings, input echoes, register results, CRC, full TX/ACK traces
and completion checks accompany the captures. This is a boundary-directed
sample, not exhaustive operand/CC or addressing-mode coverage.

### Word loads, arithmetic and comparisons

Another 1,920 records cover LDD/ADDD/SUBD/CMPD and
LDX/LDY/LDU/CMPX/CMPY/CMPU in immediate and extended-RAM forms (20 primaries).
Each uses twelve word operand pairs at CC00/01/20/21/DE/DF/FE/FF. Pairs include
0000/0000, 0000/0001, 0001/FFFF, FFFF/0001, 7FFF/0001, 8000/0001,
8000/FFFF, 00FF/0001, FF00/0100, 5555/AAAA, AAAA/5555 and FFFF/FFFF.
All 960 corresponding immediate/RAM records agree exactly.

For these cases, E/F/H/I are preserved, including H during ADDD. Loads set
N/Z from the loaded word, clear V and preserve C. ADDD sets N/Z from the sum,
V from signed overflow and C from unsigned carry. SUBD and word comparisons
set N/Z from the subtraction, V from signed overflow and C from borrow.
Compare destinations remain unchanged.

D, X, Y and U are captured in the packet. Registers other than the destination
retain their seeds. X/Y/U probes keep D=1234 while initializing the tested
register from the input table. The RAM source word at 2F40 and adjacent A5/5A
sentinels at 2F3F/2F42 remain unchanged. Literal selection for immediate forms
precedes CC restoration, with immediate capture after every fixed ROM leaf.
Source/image/table/encoding, CRC, identity, trace/ACK and completion checks pass.
S-target operations are not included here; broader operands, CC states and
addressing modes remain unmeasured.

### S-register operations and U-stack capture control

LDS and CMPS were tested in immediate and extended-RAM forms using the same
twelve word pairs and eight CC presets as the word-register matrix: 384
records. All 192 immediate/RAM pairs agree. LDS sets N/Z from the loaded word,
clears V and preserves E/F/H/I/C. CMPS preserves S, sets subtraction N/Z/V
and borrow C, and preserves E/F/H/I for the recorded inputs.

These probes use U=3FE0 to store, restore and capture CC. They contain no
S-stack push/pull instructions. S is read back before being reset to 3FF0;
D/X/Y and the restored U pointer are checked independently. Thus operands
including S=0000/8000/FFFF do not redirect explicit probe stack writes outside
work RAM. The source word and adjacent sentinels also remain unchanged.

A separate NOP control adds 768 records: all 256 initial CC values with each
of S=0000/8000/FFFF. Every CC value returns unchanged through this U-stack
capture path, D/X/Y/S remain unchanged, and U returns to 3FE0. This validates
the alternate capture path for the recorded configurations and provides NOP
flag observations. It does not broaden LDS/CMPS to all initial CC values.
All source/image, table/encoding, CRC, identity, trace/ACK, completion and
no-reset/no-drop checks pass.

### Store instructions

STA/STB/STD/STX/STY/STU/STS add 672 records: twelve source values per opcode
at CC00/01/04/05/08/09/72/FF, all using extended destination 2F40. Values span
zero, small positives, sign boundaries, alternating bits and the unsigned
maximum. Each destination starts as the source's bitwise complement, so the
readback distinguishes a completed store from an unchanged location.

Every sampled store writes the expected byte or word and preserves its source
register. N/Z describe the stored value, V clears, and E/F/H/I/C are preserved.
A5/5A sentinels immediately before and after the operand remain unchanged.
Full D/X/Y/U data is checked on the host; STS uses the U-stack capture path and
checks S against the saved input before restoring S to 3FF0. STU uses S-stack
capture, allowing arbitrary U source values. All encoding/table/hash, readback,
CRC, identity, trace/ACK, completion and no-reset/no-drop checks pass. Other
source values, CC states and addressing forms remain separate coverage gaps.

### Effective-address loads

LEAX/LEAY/LEAU/LEAS add 384 records: twelve forced extended effective
addresses (0000/0001/0002/3FFF/4000/5555/7FFF/8000/8001/AAAA/FFFE/FFFF), each
at CC00/01/04/05/08/09/72/FF. Every destination equals the encoded address.
LEAX/LEAY update only Z, which indicates a zero effective address; LEAU/LEAS
preserve every CC bit in the sample. D and untouched X/Y/U retain their seeds.

LEAS uses the validated U-stack capture path and records S before restoring it.
No S-stack push/pull is used, and LEA does not dereference these addresses.
The assembler initially shortened low addresses to direct-page forms; explicitly
forcing extended addressing resolved the encoding check before upload. All four
images pass exact restore/target/capture bytes, table/mapper/vector/hash checks,
full readback, CPU CRC, image identity, complete TX/ACK traces and no-reset/no-drop
completion. Other addressing forms and initial CC values remain coverage gaps.

ABX adds 96 records: twelve X/B pairs at those same eight CC presets. They
include zero offsets, B=80/FF, sign transitions and unsigned wrap to zero.
In every case X becomes `(X + unsigned B) & FFFF`; all CC bits and A/B/Y/U
remain unchanged. Exact restore/ABX/capture bytes and the same transport,
hash and register checks pass. This is a boundary sample, not exhaustive
operand or CC coverage.

### Explicit condition-code operations

ANDCC and ORCC add 6,144 records: each opcode at all 256 initial CC values
for masks 00/FF/55/AA/01/02/04/08/10/20/40/80. All eight flag bits follow
`CC & mask` for ANDCC and `CC | mask` for ORCC. D/X/Y/U remain unchanged.
The mask set includes every single-bit mask and both preserve-all/force-all
controls; the other mask values remain unmeasured.

Each fixed literal leaf is selected before restoring CC. The target is
immediately followed by PSHS CC; D and CC are saved before CPU register guards.
Two eight-byte records share each CRC frame. All 32 images pass exact emitted
restore/target/capture bytes, tables, mapper/vector/source/image hashes, full
readback, distinct image IDs, ordered TX/ACK traces, and no-drop/no-reset
completion. The summary checks all 256 states for every opcode/mask pair.

### Decrement-and-branch instructions

DECB,JNZ and DECX,JNZ add 3,072 records: each uses six inputs (zero, one,
two, largest positive, most negative and all ones) across all 256 initial
CC states. Both decrement modulo their operand width and branch when the
result is nonzero. N/Z describe the result, V indicates overflow from the
most-negative input, and E/F/H/I/C are preserved in every recorded case.

Each opcode has 1,280 taken and 256 untaken cases. The tested displacement
is forward +6; other offsets and boundaries remain pending. Both branch
paths immediately execute PSHS CC. DECB preserves A/X/Y/U; DECX preserves
D/Y/U, with X captured before its use as a packet pointer. Inventoried raw
AC/AD opcodes and their relative displacement are checked against assembled
labels, including the immediate CC capture at each destination. All sixteen
images pass table/hash/mapper/vector, full readback, CRC, identity, complete
TX/ACK trace, register and no-drop/no-reset checks.

### Jumps, calls and returns

JMP/JSR/BSR/LBSR/RTS add 3,840 records: each instruction across all 256
initial CC values at D=0000/1234/FFFF. Every flag and D/X/Y/U are preserved.
Calls push the exact address of the following opcode. Each case checks S:
calls leave two bytes on the stack, JMP leaves it unchanged, and RTS consumes
the prepared two-byte address. CC is captured immediately at the executed
destination, before stack or register checks. The probes cover fixed forward
ROM targets (extended JMP/JSR and relative BSR/LBSR); other target, offset,
addressing and stack-location combinations remain pending.

RTI adds 768 records: all 256 frame CC values at the same three D values.
Incoming CC is the bitwise inverse of frame CC, including the opposite E bit.
Every frame CC value is restored exactly. Frame E=0 consumes three bytes;
frame E=1 consumes twelve, checked through S after immediate destination
capture. Full frames restore D/X/Y/U from deliberately different pre-RTI
values; short frames preserve those registers. The full frame's DP byte is
00, but DP restoration has not been independently measured.

All 24 images pass exact emitted instruction, target/return and destination
capture checks, tables/mapper/vector/source/image hashes, full readback, CPU
CRC, distinct image IDs, complete ordered TX/ACK traces, data/register/stack
checks, and no-drop/no-reset completion. These are functional/flag probes;
their reporting throughput is not an instruction timing measurement.

### SETLINES bank selection and flags

Immediate and extended-RAM SETLINES add 1,536 records. Each mode tests values
00/1F at all 256 initial CC states, then every value 00..1F at
CC00/01/04/05/08/09/72/FF. The sixteen overlapping operand/CC observations per
mode are retained. All 768 corresponding immediate/RAM records agree: every
CC bit and D/X/Y/U are preserved, and the selected physical bank is value&15
under the configured 128 KiB PicoROM mask. Values 10..1F mirror 00..0F.

Each physical 8 KiB bank contains a distinct four-byte signature at offset
1B00: 5A, bank number, complemented bank number, A5. Insertion checks unused
image regions and preserves mapper, vector and communications locations.
After immediate CC capture, the CPU verifies all four signature bytes and
reports the observed bank number. It restores bank zero and checks that bank
before reporting. Extended source RAM2F40 and its adjacent A5/5A guards remain
unchanged. All encoding/table/hash, readback, CRC, identity, ordered TX/ACK and
no-reset/no-drop completion checks pass.

Only the low five input bits are varied. Physical output pins are not captured;
the address-mask aliases do not independently establish the fifth bank-output
level. Other operand values and the full bank-by-CC product remain unmeasured.

### Register-transfer encoding discrepancies

The assembler-defined EXG/TFR matrices add 576 accepted records: every ordered
pair of selectors 0..5 for primary bytes 3E and 3F, each at
CC00/01/04/05/08/09/72/FF. Exact emitted bytes are verified. Both primary bytes
exchange the selected values in these cases, including the byte labelled TFR.
Every CC bit is preserved. S remains unchanged throughout these selectors.

The observed read/write behavior fits this table for the recorded seeds:

| Selector | Value read for exchange | Destination written |
|---|---|---|
| 0 | B:A word | A from low byte |
| 1 | A:B word | B from low byte |
| 2 | X word | X word |
| 3 | Y word | Y word |
| 4 | DP-related word | word whose high byte is exposed by DP stack capture |
| 5 | U word | U word |

Seeds are A=3C, B=96, X=2193, Y=32C4, S=3FF0, U=3FE0 and selector4=A67B.
The last seed is written through verified raw encoding 3E42 before loading the
other target seeds. Exchanges from selector4 return A67B to word registers;
exchanges to it expose the received high byte through PSHS DP. This is
consistent with word-wide internal storage, whose low byte is not exposed by
the ordinary DP stack byte. Other operands, CC states, selectors6/7 and other
postbyte bits remain unmeasured; do not generalize these results to all forms.

Initial probes with A=5A/B=A5 exposed these discrepancies. A DP-byte-only seed
left state in the apparent low byte between cases, so that exploratory matrix
is retained separately. A subsequent full-word seed revealed that using U as
the capture stack for assembler-labelled S cases was wrong: exchanging U with
selector4 can put a ROM address in U. Those captures are retained and excluded.
The accepted matrix uses S for all capture, based on the measured selector map,
and reads D/X/Y/U/S plus the DP stack byte. All six final images pass exact
encodings, tables/hashes/mapper/vector, full readback, CPU CRC, image identity,
complete TX/ACK traces and no-drop/no-reset completion. All register data and
flags match the observed model; earlier failed hypotheses remain archived.

MAME and the current RTL label selector4 as S and distinguish 3E exchange from
3F transfer. Historical timing labels inherited that interpretation; their
recorded byte sequences and measured durations remain the evidence. The
coverage report now calls out this semantic discrepancy. No production RTL
correction is implied without further investigation and regression tests.

An independent fixed-instruction sweep adds 768 records, using raw encodings
3E23/3F23, 3E42/3F42, 3E20/3F20 and 3E41/3F41. Each ROM executes only one
target encoding, with no opcode dispatcher, followed immediately by PSHS CC.
The twelve X seeds are 0000/0001/0002/3FFF/4000/5555/7FFF/8000/8001/AAAA/FFFE/FFFF;
Y is X XOR A55A, selector4 is X XOR 5AC3, and D varies as 3C96 XOR (index*1111).
Each seed pattern uses the same eight CC presets as the original matrix.
All 768 observations match the table above, preserve CC and retain S3FF0/U3FE0.
All 384 corresponding 3E/3F pairs have identical outputs. This independently
confirms X/Y exchange, X/selector4 exchange, A/X exchange and B/selector4
exchange for these seeds. Selector4 initialization still uses raw 3E42, and
its output is observed through both a word register and the DP stack byte.
This does not resolve selectors6/7 or other postbyte bits. Evidence is in
`transfer-confirmation/`, with exact-byte/table checks, hashes, full readback,
CPU CRC, unique IDs BF00..BF07, complete TX/ACK traces and no-reset/no-drop
completion. These probes add operand coverage; they add no timing cases.

### Stack push/pull masks, data and flags

PUSHS/PUSHU/PULLS/PULLU add 3,456 records. Each opcode covers masks
00/01/02/04/08/10/20/40/80/55/AA/FF at CC00/01/04/05/08/09/72/FF, then masks
00/01/FF at all 256 initial CC values. Twenty-four overlapping mask/CC cases
per opcode are retained. Other masks, data patterns and stack addresses remain
unmeasured.

Pushes preserve CC and source registers apart from the stack pointer. Pulls
preserve CC unless mask bit0 is selected, in which case they load the prepared
complement of incoming CC. Selected registers restore correctly; unselected
registers are unchanged. Every frame byte and both adjacent sentinels are
checked on the CPU after immediate CC capture. Ascending byte order is
CC,A,B,DP,Xhi,Xlo,Yhi,Ylo,otherSPhi,otherSPlo,PChi,PClo for selected fields.
Pushed PC is the following opcode address. Pulled PC reaches a distinct
immediate-capture destination, with fallthrough leading to failure.

The target stack starts at 3E00; the alternate capture stack starts at 3FF0
and may be restored to 3D00 by bit6 pulls. Both pointers are captured after
the CC pop restores the capture stack. All accesses remain in verified work
RAM. Input data is A5A/BA5/X2193/Y32C4/DP37; pulled data is
A96/B3C/X2A51/Y34B2/DP69. All 36 images pass exact opcode/mask/destination,
table/mapper/vector/source/image, full-readback, CPU CRC, identity, complete
TX/ACK trace, data/register/pointer and no-reset/no-drop checks.

This finishes the first pass across all 197 known primary bytes for timing
and flags. It does not establish exhaustive operand, addressing, stack-mask,
transfer-selector or condition-code coverage for every instruction.

## Transport timeout validation

A deliberate withheld ACK exposed a bug in the original test-ROM wait loop:
`LEAU -1,U` was followed by `BNE`, although LEAU does not update Z. The original
image sent one frame and remained waiting for the full 180-second observation,
without a timeout marker or reset. The raw failed capture is retained.

The probe generator now uses `CMPU #0` after decrementing U. With the original
0800 outer count and 0FFF inner count, the physical CPU reported F2 approximately
55.94 seconds after its first frame. No ACK was sent or consumed. The capture
contains exactly the boot marker, one CRC-valid frame and F2; no further events,
resets or drops occurred during three seconds of subsequent observation.
This corrects the CPU probe, not the installed PicoROM firmware. Earlier
successful data captures do not establish timeout safety for their old images.

Reprogramming the same corrected image after timeout recovered all 96 frames
with no drops or unexpected boots. A separate seeded test set the firmware
input-sequence counter to FFFFFFF0 while ROM service was disabled and started
the CPU expected low byte at F0. All 96 frame/ACK exchanges passed, and the
final firmware counter was 00000050, proving bounded operation across both
low-byte and 32-bit wrap. This does not test billions of uninterrupted frames.

## Evidence and remaining work

The reusable build/collection/analysis tools are in [ver/pcb](../ver/pcb/README.md).
They include maintained source templates and do not require historical capture
files to build probes. The JTCORES task directory `tasks/jtkcpu-1/` holds raw
captures, manifests and reports. The principal artifact directories are
`instruction-timing/`, `framed-lmul/`, `framed-div/`, `framed-unary/`,
`packed-unary/`, `sex-confirm/`, `framed-transport/` and `watchdog-spacing/`.
Issue comments record milestones and their coverage.

The source reference for the discrepancies above is JTKCPU commit
`3dbeda84811e15a86fc91c03a082be70d1a16f1c`, including its local MAME copies.
No production RTL corrections are implied by recording these observations.
The measured collection comprises 707 timing cases and 81,772 accepted flag/result
records across all 197 known primary bytes. Every family above states its operand,
addressing and flag limits; broader combinations remain unresolved. Longer transport
interruptions and arbitrary fault recovery are also unverified. Hidden-opcode
exploration remains deferred. The old display bootstrap is retained as a simulation
fixture, while the physical tools use the validated mapper, RAM test and spaced
watchdog policy. Physical display output remains unconfirmed.

Reproduction checks built all thirteen timing families from a clean output
directory and reproduced six representative images byte-for-byte. Physical
transport, scalar timing and full-mask stack reruns passed. Twelve host tests
run without hardware or historical captures. Simson lint passes both `game_test`
and `jtframe_board` using Verilator5.018 with only its unsupported `--quiet-stats`
option omitted by a task-local wrapper; both underlying exit codes are recorded.
This validates syntax, not agreement of RTL behavior with the PCB findings.

## RTL regression handoff

[Focused assembly regressions](../ver/top/tests/pcb/README.md) retain six exact
physical vectors for SEX, byte ROL, LMUL, DIV, ABS and DAA. They currently fail
against the unchanged RTL while a matching capture control and existing
sex/andcc/orcc/pshs tests pass. Logged D/X/Y agree with the PCB for all six;
the captured CC bytes identify the discrepancies. In particular, the LMUL
vector exposes a Z mismatch as well as C when its high product word is zero
and its low word is nonzero. These are explicit failing regression cases
outside the normal batch glob, with proposed correction scope and provenance.
